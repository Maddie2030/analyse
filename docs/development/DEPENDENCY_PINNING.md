# Dependency pinning policy — v1.3.0-rc4.52

RC4.37 rejects floating direct dependency declarations in supported build/deploy paths.

- Python requirements use `package==x.y.z` only.
- Shared Python runtime dependencies use exact `==` pins.
- npm direct dependencies/devDependencies use literal patch-exact semver (no `^`, `~`, ranges, `latest`, `next`, `x`, or `*`).
- The frontend uses its committed `package-lock.json` and `npm ci`.
- Go modules and Go language/toolchain directives are exact; `go.sum` remains committed.
- OpenTofu/Terraform and provider constraints use exact `=` versions.
- KEDA, Metrics Server, Cosign, Helm/chart tooling, Docker/base image tags, and explicitly installed OS packages are exact versions. Playwright images are also digest-pinned.

`tests/regression/dependency-pins.sh` enforces these rules.

## npm transitive lock status

The frontend dependency graph is transitively locked. `services/social_ts` and `tests/browser` currently have exact direct dependency declarations but do not yet carry generated npm lockfiles in this offline-packaging environment. Their Docker builds therefore resolve transitive npm dependencies at build time. Do not describe those two graphs as bit-for-bit reproducible until lockfiles generated by npm for the pinned manifests are committed.
