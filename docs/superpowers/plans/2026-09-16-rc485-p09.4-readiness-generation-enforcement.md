# RC4.85 P09.4 Readiness and Restore-Generation Enforcement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the supported hybrid deployment and restore/restart path fail closed unless current migrations, P09.3 effective PostgreSQL grants, workload-scoped DSNs, restore-generation state, current Deployment templates, rollout, and autoscaling are reconciled in one canonical order.

**Architecture:** Reuse P05 quiescence, P09.3 grant reconciliation, P08.8 host restore control/database mirror, and the existing hybrid deploy path. Add one host-side P09.4 readiness gate that emits a deterministic non-secret deployment-generation token only after live schema/grants/credentials/generation are verified; render that token into current Deployment templates before apply, prove rollout, and only then restore HPA/KEDA. Restore/restart must re-enter the same deploy path instead of directly applying workload/autoscaling manifests.

**Tech Stack:** Bash, Python 3 standard library, PostgreSQL/psql via existing Docker Compose DB service, Docker Desktop Kubernetes/kubectl, existing JSON ownership contracts, unittest dependency-light regressions.

**Spec:** `docs/superpowers/specs/2026-09-16-rc485-p09.4-readiness-generation-enforcement-design.md`

## Global Constraints

- Preserve P09.3 `contracts/ownership/postgres-roles.v1.json` as the only runtime PostgreSQL privilege authority; do not create a second grant model.
- Preserve P08.8 host restore control as primary; `database_restore_state` remains only a PostgreSQL mirror.
- Preserve P09.1 workload env-scope allowlists; no application workload may receive bootstrap `POSTGRES_USER`/`POSTGRES_PASSWORD` fallback credentials.
- Preserve P05 ordering: autoscalers lose authority before quiescence and regain authority only after current workload rollout succeeds.
- `database_restore_state` mismatch is observed and blocks readiness; P09.4 must not repair it by choosing a generation.
- The deployment-generation token is deterministic and non-secret; it binds committed restore generation, installation-fingerprint digest, latest migration identity, and P09.3 role-contract hash/version.
- Every PostgreSQL workload declared by the P09.3 contract, including replica-zero KEDA workers, must receive the current generation in its Deployment pod template before autoscaling is restored.
- Keep checked-in Kubernetes application manifests generation-neutral; render temporary generation-stamped manifests at deploy time.
- Do not add Helm/Kustomize, a readiness service, another restore catalog/store, or a second operations queue.
- P09.5 route/consumer denial is out of scope.
- Real Docker/Kubernetes/PostgreSQL P09.4 qualification is PASS only when actually executed; absent runtime prerequisites are BLOCKED, never inferred from source tests.
- P09.3's real PostgreSQL permission gate remains a separate blocker until actually executed.
- Forensic `refs/stash` (`ffbcfe842c0e7f0910eae8ccf4fe64f822c01af4`) must never be applied or popped.
- After the final meaningful P09.4 source checkpoint and separate tracker/handoff checkpoint, regenerate the all-refs bundle, immutable/current continuation ZIPs and sidecars, persist them to Library, re-materialize both Library ZIPs, and independently verify tracker HEAD, source ancestry, 19 advertised heads / 17 real refs, internal checksums, and exact stash before calling P09.4 durable.

- [ ] **Step 4: Render live readiness SQL**

```sql
\set ON_ERROR_STOP on
BEGIN;
DO $p094$
DECLARE restore_rows integer;
BEGIN
  IF NOT EXISTS (SELECT 1 FROM schema_migrations WHERE version = :'latest_migration') THEN
    RAISE EXCEPTION 'P09.4 schema-not-ready: latest migration missing';
  END IF;
  SELECT count(*) INTO restore_rows FROM database_restore_state WHERE singleton = TRUE;

    RAISE EXCEPTION 'P09.4 generation-not-ready: host/database mirror mismatch';
  END IF;
END
$p094$;
ROLLBACK;
```
