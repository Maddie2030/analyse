## Why P06.3 is not yet complete

### 1. Real PostgreSQL transaction gate has not executed

`services/catalog_go/internal/store/publication_postgres_test.go` contains response-loss/receipt replay, same-key/different-body, concurrent stale-replacement, cancellation/source/generation fence, actor authorization, concurrent-create and Media-evidence immutability cases. `services/notification_worker/internal/store/chapter_published_postgres_test.go` additionally contains the revision-scoped Notification dedupe case for v2 plus legacy-v1 compatibility. These real PostgreSQL cases have **not run** in this workspace. The Catalog module requires Go 1.25.0 while the available Go is 1.23.2; no PostgreSQL server/client or disposable `MREADER_TEST_POSTGRES_DSN` is available.

A written/skipped DB test is not runtime verification.

A guarded runner now exists at `scripts/test/p06-3-postgres-gate.sh`. It permits Go 1.25+ or an auto toolchain launcher and executes the Catalog `TestCommitPublication*` transaction suite plus `TestMediaCompletionEvidenceIsDatabaseImmutable`, then runs Notification Worker `internal/events` and `internal/store` (including `TestChapterPublishedV2DedupeIsPublicationRevisionScoped`) in either of two explicit modes:

- external disposable DB: set `MREADER_TEST_POSTGRES_DSN=...` and `MREADER_TEST_POSTGRES_CONFIRM=disposable`;
- Docker-provisioned disposable runtime: run `MREADER_TEST_POSTGRES_MODE=docker ./scripts/test/p06-3-postgres-gate.sh`.

Docker mode refuses an external DSN, creates an isolated Docker network, starts the pinned `postgres:16.10-alpine3.22` image with tmpfs-only database storage and no persistent volume, applies the real migration renderer, and runs the exact P06.3 tests inside the project-standard `golang:1.25.0-alpine3.22` image. Because Catalog intentionally does not commit `go.sum`, commit `2dbc64d` keeps the repository bind mount read-only, copies `services/catalog_go` into writable container scratch, pins `GOTOOLCHAIN=local`, then runs `go mod tidy`, `go mod verify`, and the focused transaction tests. Commit `ffc166f` also digest-pins the Go image to `golang:1.25.0-alpine3.22@sha256:f18a072054848d87a8077455f0ac8a25886f2397f88bfdd222d6fafbb5bba440` so the qualification toolchain cannot drift behind the tag. It removes both the database container and temporary network on success or failure. The gate-harness regression is **8/8**, including writable-module preparation, a case with no host Go binary available, Notification consumer compilation/testing, teardown, and ambiguous-target rejection.

This workspace still cannot execute the real database gate because Docker is absent. Docker mode no longer depends on host Go or host PostgreSQL; on a Docker Desktop host it supplies both runtimes itself. It is **not an offline bundle**: first use still requires the pinned Docker images and the Catalog Go modules to be available from cache or reachable registries/module proxies. Runtime confirmation therefore remains open in this sandbox because there is no Docker daemon, and the real transaction assertions have still not executed.

### 2. Transaction authority/fence source gap is repaired by the prerequisite detour

The P06.3 prerequisite branch introduces migration 055 and the canonical `ingestion_operations` header. For a **new** Catalog commit, `Store.CommitPublication` now locks the operation header and verifies the retained requesting actor, exact source revision, exact lease/fencing generation, cancellation request/status, `running` state, and the actor's current `users.is_active` + `role='admin'` authorization before Media evidence or Catalog target mutation. Durable receipt lookup remains first so a response-loss retry does not depend on later ingestion state, but `2a9ff5c` now rechecks the actor's **current** `users.is_active` + `role='admin'` authorization before returning that recorded receipt. Operation cancellation/revision/generation checks remain intentionally skipped after a proven commit; current actor authorization does not.

The workload credential itself is deliberately not guessed inside the store. P06.5 remains the transport-authentication owner: the future private `/internal/v1/catalog` handler must authenticate the workload credential before it is allowed to call this store boundary. P09.1 remains the prerequisite for distributing that private credential narrowly. Because no private handler is registered in P06.3, this split does not create an unauthenticated HTTP publication route.

### 3. Concurrent-publication source coverage is now explicit

`publication_postgres_test.go` now includes a separate concurrent-create/same-target race in addition to the stale-replacement race. It expects exactly one authoritative chapter/receipt and one conflict. The test is written and source-reviewed but remains unexecuted until the real PostgreSQL/Go runtime gate is available.
