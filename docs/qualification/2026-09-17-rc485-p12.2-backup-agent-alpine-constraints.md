## Real-host failure

The pre-upgrade recovery validator correctly fell back to the `backup_agent` runtime when host `jq` was unavailable, but Docker could not build that image:

```text
RUN apk add --no-cache bash=5.2.37-r0 jq=1.8.2-r0 coreutils=9.7-r1 tzdata=2026c-r0
failed to solve: ... apk add ... exit code: 2
```

The Dockerfile exact-pinned mutable Alpine v3.22 package revisions. The current stable repository no longer satisfies that exact set (`jq` on v3.22 is 1.8.1-r0 and `tzdata` has advanced to 2026d-r0), so the image became unbuildable even though the required package capabilities remain available.

## Repair

The PostgreSQL base image remains digest-pinned. Runtime packages now use minimum-compatible Alpine constraints instead of exact `-rN` revisions:

```text
bash>=5.2.37
jq>=1.8.1
coreutils>=9.7
tzdata>=2026a
```

The dependency policy checker was updated to understand `>` inside Alpine version constraints and still rejects genuinely unversioned OS packages. It also explicitly rejects reintroducing exact mutable `-rN` pins for the backup-agent runtime package set.
