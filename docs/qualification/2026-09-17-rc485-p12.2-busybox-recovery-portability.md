## Real-host failure

After the no-host-`jq` fallback successfully built and launched the Alpine backup-agent container, canonical recovery validation failed with:

```text
find: unrecognized: -printf
BusyBox ...
ERROR: recovery bundle contains missing or unexpected files
ERROR: local recovery bundle failed canonical validation; no recovery bundle was published.
ERROR: mandatory local pre-upgrade recovery capture failed (exit=4); migrations were not run.
```

The backup-agent image is Alpine/BusyBox-based. `scripts/backup/local-recovery-store.sh` used GNU `find -printf` to enumerate bundle filenames. BusyBox `find` does not implement `-printf`, so enumeration failed before comparison with the expected bundle inventory. A second GNU-only `-printf` existed in `scripts/backup/backup-agent.sh` for latest-migration discovery.

## Repair

`e5f0af1e9cacd369f3ec4b2b5b2c92a3617b4d3e` removes active GNU-only `find -printf` use from the Alpine backup runtime:

- recovery bundle file enumeration now uses `find ... -print0` and Bash `${item##*/}` basename extraction;
- latest-migration discovery uses the same `-print0` pattern;
- NUL-delimited enumeration preserves spaces safely;
- canonical recovery validation remains fail-closed;
- no `findutils` package was added solely to emulate GNU behavior.
