## Repair

`f12f26188b4c08d904b52ff1cadbe8bdab929ecb` changes bootstrap precedence only when the saved root is blank:

1. a valid explicit process-level override is still honored;
2. an invalid inherited process value is treated as stale shell state;
3. bootstrap retries through the shared resolver with no process override, which yields `C:/mreader/database-protection` on Windows;
4. the resolved root is persisted into `.env`, exported, and created before stateful adoption/preflight;
5. when `.env` already contains an explicit root, the existing process-vs-saved disagreement fence remains unchanged.

No backup/restore/readiness caller was forked or given independent path logic; they continue to consume the one shared saved root.
