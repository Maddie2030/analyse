## Real-host failure

After pre-upgrade recovery validation succeeded far enough to continue through migrations, P09.4 stopped with:

```text
P09_4_READINESS=generation-not-ready cannot read restore control: C:/mreader/database-protection/control/restore-control.json
```

Migration `060_database_restore_fencing.sql` intentionally initializes the PostgreSQL singleton restore mirror with an empty installation fingerprint and generation `0`. P09.4 correctly requires a persistent positive generation and exact host/database agreement, but the fresh initialization path never created the host restore control or seeded the database mirror before readiness ran.

## Repair

`4fbd847af7ae6f7a2f0bd8704ae34bc272fc8f4f` adds a fail-closed initialization step:

- backup agent command `initialize-restore-state` obtains the canonical host restore control (generation `1` on first initialization);
- it atomically seeds `database_restore_state` only while the singleton remains the migration default (`installation_fingerprint=''`, `restore_generation=0`);
- if host and database already match, the operation is idempotent;
- any non-default mismatch still raises an error instead of rewriting restore history;
- `stateful-up.sh` invokes the command after migration and PostgreSQL role reconciliation, before P09.4 readiness/deployment proceeds;
- the initialization contract is included in `scripts/hybrid/validate.sh`.
