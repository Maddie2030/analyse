## Real-host failure

Windows/Git-Bash bootstrap repeatedly progressed through hybrid validation to:

```text
hybrid pre-upgrade backup ordering regression PASSED (backup line 25 < migration line 48)
hybrid PostgreSQL volume inspection static regression PASSED
Created .env from .env.example
ERROR: Use an absolute Windows drive path, such as C:/Users/name/.mreader/database-protection.
```

The operator's actual project environment was already valid: `MREADER_DB_PROTECTION_ROOT=C:/mreader/database-protection`, and direct tracing of `scripts/env/resolve-db-protection-root.sh .env` returned that exact value successfully.

## Root cause

The error was emitted by a nested regression, not by the project `.env` path. `scripts/hybrid/validate.sh` line 99 invokes `tests/regression/bootstrap-fresh-env.sh`. That regression always exported `MREADER_DB_PROTECTION_ROOT=$TMP/recovery with spaces`. The fixture is an absolute POSIX path on Linux, but on Git Bash it is not a Windows drive-form path, so the shared resolver correctly rejected the test fixture.

The exact Windows-path error string exists only in `scripts/env/db-protection-root.sh`; all production backup/restore/startup consumers continue to route through that one shared resolver.

## Repair

`3020fc30bbbf1bd8fd7e89ce31145847469710c9` changes only `tests/regression/bootstrap-fresh-env.sh`:

- MINGW/MSYS/Cygwin uses `cygpath -m` to convert the temporary fixture to a Windows drive-form path while preserving the path-with-spaces test;
- Linux keeps the original POSIX temporary path;
- simulated Windows CI without `cygpath` uses a bounded drive-form fixture.

No production bootstrap, resolver, backup, restore, readiness, or mount behavior changed in this repair.
