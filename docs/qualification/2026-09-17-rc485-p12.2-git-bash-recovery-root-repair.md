## Real-host failure

Real Windows/Git Bash deployment progressed through pre-upgrade ordering and PostgreSQL volume inspection, then a fresh `.env` was created from `.env.example` and bootstrap stopped with:

```text
ERROR: Use an absolute Windows drive path, such as C:/Users/name/.mreader/database-protection.
```

The failure was caused by recovery-root normalization accepting `C:/...` and `C:\\...` forms but not the normal Git Bash/MSYS `/c/Users/...` form. It also required `USERPROFILE` even when Git Bash `HOME=/c/Users/...` was available. This contradicted the intended first-run behavior where bootstrap derives and persists the dedicated recovery root automatically.

## Repair

`6f32a597951bf3c5516389a86e3ad5b3064ad677` canonicalizes Windows/MSYS drive paths such as `/c/Users/Reader` to `C:/Users/Reader` before validation and falls back to Git Bash `HOME` only when `USERPROFILE` is unavailable. Existing explicit/configured recovery roots, traversal/UNC rejection, broad-directory rejection, duplicate-root fencing and process-vs-saved disagreement checks remain intact.
