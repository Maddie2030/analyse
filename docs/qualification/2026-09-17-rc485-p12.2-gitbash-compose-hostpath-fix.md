## Real-host failure

On Windows/Git Bash, PostgreSQL capture reached the no-host-`jq` fallback but Docker Compose rejected the Compose-file path as:

```text
C:\\c\\Users\\madhu\\...\\deploy\\compose\\docker-compose.hybrid-stateful.yml
```

The fallback correctly set `MSYS_NO_PATHCONV=1` to preserve Linux container paths such as `/mreader-db-protection/...`, but that also prevented Git Bash from converting the Windows host paths used for `--env-file` and `-f`. Docker then interpreted the raw `/c/Users/...` path as `C:\\c\\Users\\...`.

## Repair

`8b1415a8c330816e459ad5e7c29b73336961a105` keeps `MSYS_NO_PATHCONV=1` for the fallback command, but preconverts only the host-side paths before invoking Docker Compose:

- `.env`/`--env-file` path -> native `C:/...` form on MINGW/MSYS/Cygwin;
- Compose `-f` path -> native `C:/...` form on MINGW/MSYS/Cygwin;
- container recovery paths remain `/mreader-db-protection/...` and are never rewritten.

The conversion uses `cygpath -m` when available with a guarded `/c/...` fallback. Linux behavior is unchanged.
