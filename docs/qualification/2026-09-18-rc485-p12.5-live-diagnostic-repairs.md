## Evidence that drove the repair

The real-host actor/browser diagnostic report separated harness defects from application defects. The confirmed root causes were:

1. API pytest collection stopped before actor journeys because the API test image/runtime lacked two helper contracts (`zip_image_chapter`, `wait_series_draft_terminal`) and the pinned `asyncpg` dependency.
2. Admin series creation returned HTTP 500 because `catalog_admin` could not mutate Catalog-owned taxonomy join tables such as `series_genres`.
3. Smart Library/Social reads required `reading_state_v1`, but `social_runtime` lacked the required `SELECT` grant.
4. The live Progress database also showed grant drift from the already-declared contract. Existing deployments therefore need the normal post-migration role reconciliation path, not only a fresh-schema contract edit.
5. Realtime browser acceptance assumed registration implied an authenticated browser session; the current contract requires explicit login before WebSocket setup.
6. Admin browser database assertions were stale relative to the current privacy-safe database/recovery UI.

## Repairs

- Restore the missing API-test helpers and install pinned `asyncpg` in the API-test image.
- Add canonical `ApiSession.get_json()` and reuse it instead of cloning fetch/poll behavior.
- Declare Catalog taxonomy write ownership for `genres`, `tags`, `series_genres` and `series_tags` and render the corresponding runtime grants.
- Grant `social_runtime` read access to `reading_state_v1`.
- Preserve/verify upgrade-time role reconciliation so existing databases receive repaired grants when `./hybrid-up.sh` runs.
- Require explicit login in the realtime browser journey after registration.
- Align admin database browser acceptance with the current privacy-safe surface.
- Add `tests/regression/test_p12_5_live_diagnostic_repairs.py` to the permanent current-release validator.
