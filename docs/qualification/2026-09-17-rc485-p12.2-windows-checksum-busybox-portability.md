## Real-host failure

After the Alpine backup-agent image built and BusyBox `find` portability was repaired, canonical recovery validation failed with:

```text
ERROR: checksum manifest contains an unsafe or duplicate entry
ERROR: local recovery bundle failed canonical validation; no recovery bundle was published.
ERROR: mandatory local pre-upgrade recovery capture failed (exit=4); migrations were not run.
```

The staged checksum file is generated on the Windows/Git-Bash host. GNU `sha256sum` may encode binary-mode entries as `HASH *filename`. The canonical validator accepted only `HASH  filename`, so valid Windows-generated manifests were rejected as unsafe. The next verification command also used GNU-only `sha256sum --strict --status -c`, which BusyBox `sha256sum` does not support.

## Repair

`9793fed4a7b5f9e47a5b3950826e6bfae1aa8e4c` makes canonical checksum validation portable without weakening the allowlist:

- accepts both standard text-mode and GNU binary-mode checksum markers;
- strips only the optional leading `*` marker before exact filename allowlist and duplicate checks;
- mixed `filename` / `*filename` aliases are treated as the same identity and rejected as duplicates;
- replaces GNU-only `sha256sum --strict --status -c` with portable `sha256sum -c` after the manifest has already passed strict structural validation;
- checksum verification remains fail-closed.
