## Real-host failure

Windows/Git-Bash pre-upgrade capture advanced past the prior MSYS `/tmp` path repair, then failed during canonical recovery-store validation with:

```text
Creating verified local pre-upgrade PostgreSQL recovery bundle...
ERROR: required recovery-store tool is missing: jq
ERROR: local recovery bundle failed canonical validation; no recovery bundle was published.
ERROR: mandatory local pre-upgrade recovery capture failed (exit=4); migrations were not run.
```

The PostgreSQL dump/copy itself was no longer failing. The host-side `local-recovery-store.sh publish-staged` validator required `jq`, which was not installed in the Windows Git-Bash host environment.

## Repair

`c9dde2b278cda2d67e3ad672d3935fdd06e7a045` preserves fail-closed canonical validation while removing the host `jq` dependency from this path:

1. if host `jq` exists, the existing host recovery-store validator is used unchanged;
2. if host `jq` is missing, `create-local-preupgrade-backup.sh` runs the same `/usr/local/bin/mreader-local-recovery-store` validator through the `backup_agent` image;
3. the existing host database-protection root remains mounted as `/mreader-db-protection`;
4. `MSYS_NO_PATHCONV=1` protects container-internal recovery paths from Git-Bash rewriting;
5. canonical validation still fails closed if the backup-agent validator fails.

The backup-agent image already pins `jq` and GNU coreutils, so no new host package is required.
