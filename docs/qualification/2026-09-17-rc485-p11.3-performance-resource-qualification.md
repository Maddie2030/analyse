## Smart Library query-plan audit boundary

The Smart Library endpoint remains one PostgreSQL statement. Its base relation is assembled from user-scoped bookmark, subscription, and `reading_state_v1` identities; summary, page, and recent-reading projections are materialized from that base in the same statement. Page size is clamped to at most 100 and the recently-opened projection is capped at 12.

The source tree contains supporting ownership/navigation indexes, including user+series uniqueness for bookmarks/subscriptions, reading-progress/chapter-read user+series indexes, and the published chapter navigation index on `(series_id, chapter_number DESC)`.

This is **source/index-shape evidence only**. PostgreSQL is unavailable, so P11.3 did not execute `EXPLAIN (ANALYZE, BUFFERS)` and cannot claim that the real planner uses a particular index, avoids spill/sort pressure at realistic cardinalities, or meets a measured latency/IO budget.
