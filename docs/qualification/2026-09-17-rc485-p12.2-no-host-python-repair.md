
This was a source/package regression, not an operator prerequisite failure. The retained Docker Desktop deployment documentation explicitly states that host Python is not required. ## Repair

`3397e5c` adds `scripts/hybrid/python-runtime.sh` as the single shell-side Python resolver. It selects an already available `python3`, `python`, or Windows `py -3`; when none exists it requires the already-mandatory Docker Engine and executes pinned `python:3.12.11-slim-bookworm` with repository/path mapping suitable for Git Bash. P09.4 temporary files that must be visible to a Docker fallback are created under ignored `.runtime/`.

All direct executable host `python`/`python3` shell invocations under `scripts/` and `tests/` were removed. The regression now scans the whole shell surface and explicitly exercises the forced Docker-fallback path.
